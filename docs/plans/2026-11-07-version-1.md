# Version 1 – Jobradar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jeden Tag automatisch die offenen Stellen von 13 Unternehmen abrufen, vorfiltern, speichern und auf einer Website mit Filtern anzeigen, die auf Handy und Laptop funktioniert.

**Architecture:** Ein Python-Skript (`scraper/run.py`) ruft pro Unternehmen einen ATS-Adapter auf, also eine kleine Datei für jedes Bewerbersystem. Es filtert die Stellen, gleicht sie mit `data/jobs.json` ab (neu, weiterhin offen, geschlossen) und schreibt `site/daten.json`. Eine statische Seite (`site/index.html` + `app.js`) filtert diese Daten im Browser. GitHub Actions startet den Lauf täglich, speichert die Daten per Commit im Repo und veröffentlicht `site/` über GitHub Pages.

**Tech Stack:** Python 3.12 (`requests`, `pytest`, später `beautifulsoup4` nur für HTML-Adapter), HTML/CSS/JavaScript ohne Framework, GitHub Actions, GitHub Pages.

**Spec:** `CLAUDE.md` (Abschnitte 3–5, 9–10) und die Entscheidungen in `docs/ENTSCHEIDUNGEN.md`.

## Global Constraints

- Abrufe: User-Agent `jobradar/1.0 (+https://github.com/testgaly99/jobradar)`, höchstens 1 Anfrage pro Sekunde pro Domain, `robots.txt` wird beachtet (Verbot → Unternehmen wird übersprungen und im Bericht genannt).
- Kein Sprachmodell im Betrieb. Keine kompletten Stellentexte: `beschreibung_kurz` hat höchstens 300 Zeichen Klartext.
- Stellen werden nie gelöscht. Was beim Abruf fehlt, bekommt `status: "geschlossen"`.
- Ein Fehler bei einem Unternehmen bricht den Lauf nicht ab.
- Spalten in `companies.csv`: `name, careers_url, ats_typ, ats_id, groesse_klasse, mitarbeitende_ca, kategorie, hauptsitz, aktiv, notiz`. `groesse_klasse` ∈ {`<50`, `50–249`, `250–999`, `1.000+`}. `kategorie` = eine oder mehrere Kategorien aus `data/kategorien.md`, getrennt durch `;`. `aktiv` ∈ {`ja`, `nein`}.
- Felder einer Stelle: `id, unternehmen, titel, ort, remote, url, erstmals_gesehen, zuletzt_gesehen, beschreibung_kurz, status`.
- Vorfilter: nur Deutschland plus Remote (Europa/EMEA/Deutschland). Ausgeschlossen werden Stellen mit diesen Wörtern im Titel (Groß- und Kleinschreibung egal): Ausbildung, Azubi, Auszubildende, Duales Studium, Dual, Praktikum, Praktikant, Intern(ship), Werkstudent, Working Student, Bachelorarbeit, Masterarbeit, Abschlussarbeit, Thesis, Minijob, Aushilfe, Verkäufer, Filiale, Kassierer. Ausdrücklich drin bleiben: Trainee, Graduate, Junior.
- Commit-Nachrichten auf Deutsch. Vor jedem Commit prüfen, dass keine Geheimnisse enthalten sind. Für Version 1 gibt es keine.
- Python wird unter Windows mit `py`, im Workflow mit `python` aufgerufen.

## Review Focus

1. **Ortsangaben mit mehreren Orten oder Kleinstädten** („Munich - London“, „Gilching“): Die Stelle bleibt drin, wenn ein deutscher Ort darin vorkommt. → Test in Task 3.
2. **Remote außerhalb Europas** (Taktile: „New York Office“, `isRemote: true`): Die Stelle fällt raus. → Test in Task 3.
3. **„Intern“ als Teil eines anderen Wortes** („International Sales“, „Internal Audit“): Die Stelle bleibt drin, weil nur ganze Wörter zählen. → Test in Task 3.
4. **Ein Unternehmen liefert 0 Stellen oder Fehler**: Die bisherigen Stellen dieses Unternehmens werden bei einem Fehler **nicht** als geschlossen markiert. → Test in Task 6.
5. **Der Zeitplan ist still abgeschaltet** (60-Tage-Regel für öffentliche Repos): Die Website zeigt einen Warnhinweis, wenn der letzte Lauf älter als 2 Tage ist. → Task 8.

### Task 7: Gesamtlauf und Bericht

**Files:** Create `scraper/run.py`, Test `tests/test_run.py`

**Interfaces:**
- Consumes: `lade_unternehmen`, `ADAPTER`, `ist_relevant`, `abgleichen`/`lade`/`speichere`
- Produces: `lauf(heute: str, datenordner="data", seitenordner="site") -> dict` (Bericht). Ablauf für jedes Unternehmen mit `aktiv == "ja"`:
  1. Adapter aufrufen. Bei Exception: Fehler mit Grund in den Bericht, Bestand dieses Unternehmens **nicht** anfassen, weiter mit dem nächsten.

  3. `abgleichen`.
- Schreibt `data/jobs.json`, `data/bericht.md` (Tabelle: Unternehmen | gefunden | gefiltert | neu | geschlossen | Fehler) und `site/daten.json` = `{"stand": heute, "unternehmen": [...companies ohne notiz...], "stellen": [nur status offen]}`.
- Aufruf: `py -m scraper.run`. Exit-Code 1 nur, wenn **alle** Unternehmen fehlschlagen.

- [ ] Tests mit einem Fake-Adapter (`monkeypatch` auf `ADAPTER`): `test_fehler_bricht_nicht_ab` (Firma A wirft, Firma B liefert → B ist gespeichert und A steht im Bericht), `test_fehler_schliesst_nichts` (die offenen Stellen von A bleiben `offen`), `test_daten_json_enthaelt_nur_offene`

**Interfaces:**
